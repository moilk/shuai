# App icon and brand assets

The icon is generated by `tools/icongen` from text configuration in `brand/`; see
[ADR 0007](../adr/0007-programmatic-brand-icon.md) for why. The canonical glyph source is
`brand/source/oracle-rate.png` (the oracle-bone character 率); the committed vector mark
`brand/mark/mark.toml` is traced from it and measured against it.

## Regenerating

```sh
cd tools/icongen
cargo run --release -- generate     # writes brand/out/** and the AppIcon asset catalog
cargo run --release -- check        # CI: committed outputs match a fresh generate
cargo run --release -- fidelity     # CI: the mark still matches the source raster
cargo test
```

Commit the regenerated files with the change that caused them. Defaults assume the working
directory `tools/icongen`; pass `--brand DIR` otherwise.

## Layout

| Path | Contents |
|---|---|
| `brand/icon.toml` | Canvas `size`, which theme each iOS appearance uses, `appiconset` path |
| `brand/themes/<name>.toml` | One theme: background, texture, mark, gloss, container |
| `brand/mark/mark.toml` | The traced master glyph |
| `brand/source/oracle-rate.png` | Canonical glyph raster (input of the tracer and of `fidelity`) |
| `brand/out/<light,dark,tinted>/` | Layer SVGs (`base`, `texture`, `mark`, `gloss`, `container`, `composite`) and `icon.png` |
| `brand/out/exports/` | `mark.svg` (transparent, black), `mark-light.svg` (transparent, ivory), `favicon-{16,32,48}.png`, `readme-256.png` (squircle) from the mono themes |
| `brand/out/manifest.json` | Mark bounds per appearance |
| `apple/App/Resources/Assets.xcassets/AppIcon.appiconset/` | `AppIcon-{light,dark,tinted}.png` (copies of the rendered icons) and `Contents.json` |

`appiconset` in `icon.toml` is a plain path relative to the repository root; with a custom
`--brand DIR` it resolves to `DIR/../<appiconset>`.

`check` compares SVG and JSON numerically (numbers within 1e-3, all other text exactly) and PNGs
within +-2 per channel, so platform float formatting does not fail it but any structural change does.

## Configuration

`icon.toml`:

```toml
size = 1024
appiconset = "apple/App/Resources/Assets.xcassets/AppIcon.appiconset"

[appearances]
light = "matte"
dark = "matte"
tinted = "tinted"
```

A theme (`brand/themes/matte.toml`) has these tables; unknown keys are rejected:

- `[background]`: `kind = "solid" | "linear"`, `color` (`#rrggbb`), `color2` and `angle` for linear.
- `[texture]`: `enabled`, `seed`, `grain`, `cracks`, `motifs`, `color`, `opacity`, `keepout` (margin
  kept clear around the mark). The texture is deterministic from `seed`.
- `[mark]`: `fill`, `scale` (mark size as a share of the canvas), `offset`, `weight`, `hole_weight`,
  optional `small_size = { max_px, weight }`.
- `[gloss]`: `enabled`. `[container]`: `kind = "none" | "squircle"` (squircle clips and outlines
  with a border of 2/1024 of the canvas).

Numbers are validated: all finite, `grain` 0..=1, `keepout` 0..=0.5, `opacity` 0..=1, `cracks` at
most 200, `motifs` at most 64, `offset` within -0.5..=0.5.

### Weight and hole_weight

`weight` is a uniform mitred outline offset in source pixels (0 is the master carving, limit 6).
It grows every piece; `hole_weight` (default: `weight`, never larger) is how far the S01 counters
shrink, so a lower value keeps the holes open on a heavier mark. The shipped themes all use
`weight = 2.1`, `scale = 0.75`, `hole_weight = 1.0`; changing these changes fidelity, so re-run
`fidelity` and review.

## mark.toml

Coordinates are source pixels, y down, so weight 0 overlays the source raster 1:1.

- `[s01]`: `outline = [[x, y, tag], ...]` and `holes = [[...], ...]` (even-odd fill).
- `[[stroke]]` (S02..S05): `id` and either `outline` (closed polygon, as produced by the tracer) or
  a hand-written centerline `points` with per-point widths and chisel end caps, converted to an
  outline when parsed.
- Every vertex carries a tag: `c` is a sharp carved corner (kept exactly, never curved), `s` is
  smooth (rendered as a smoothed curve between neighbours).

### Tracer

`icongen trace --source brand/source/oracle-rate.png --out brand/mark/mark.toml` upsamples the source
4x with a bicubic (Catmull-Rom) kernel, takes the 50% iso-contour (the source is a binary
black-and-white glyph, so the anti-aliased edge gives sub-pixel positions), smooths each contour
between carved corners (Gaussian, sigma 1.0 source px), simplifies with Douglas-Peucker
(eps 0.1 px), and anchors detected corners as `c` vertices. The result is a dense outline per
piece. Re-tracing overwrites hand edits, so do it deliberately and run `fidelity`.

## Fidelity gates

`icongen fidelity` compares the master mark (weight 0), rasterised at 4x, with the source:

| Metric | Gate |
|---|---|
| IoU of the whole mark | >= 0.975 |
| Hausdorff distance | <= 1 source px |
| Area difference | within +-1% |
| IoU per piece (S01..S05) | >= 0.96 |
| Carved corners kept | >= 90% |
| Topology | 5 pieces, 2 holes (S01 has 2 holes and 4 strokes) |

It also checks small renders (120, 60, 40 px: piece and hole counts, narrowest stroke >= 2 px at 60
px) and every theme at 1024, 120, 60 and 40 px: topology preserved, holes keep at least 12 source
px squared and 60% of their master area, strokes hold about 2 px at 40 px. Unit tests additionally
require 7:1 contrast between mark and background in each theme.

## Adding or changing a theme

Backgrounds, textures and colours never touch the glyph: copy `brand/themes/matte.toml` to a new
name, edit `[background]` and `[texture]` (keep `[mark]` unchanged to keep fidelity), point an
appearance at it in `icon.toml` (or use it only for exports), then `generate`, `check`, `fidelity`.
Theme names are lowercase letters, digits and `-`. `mono-dark` and `mono-light` are export-only
themes used for `out/exports/`.

## Known limitations

- Hole gates are not evaluated at the `small_size` bonus sizes (60 and 40 px). No shipped theme
  uses `small_size`; enable the gates before shipping one that does.
- Texture margins (`EDGE`, 20 px) are absolute pixels, so small-size texture renders are not
  scaled copies of the 1024 render. Only the 1024 px texture is shipped.
- A stroke given as a centerline (`points`) gets no self-intersection loop removal at bends
  sharper than about 60 degrees. The shipped master uses the `outline` format.

## Liquid Glass and iOS 26

The asset catalog is the iOS 18 single-size icon with dark and tinted appearances.
`scripts/check-app-icon.sh` verifies the compiled `Assets.car` has all three (self-test:
`scripts/test-check-app-icon.sh`). On iOS 26 and later the system draws its own glass treatment over
icons that are not an Icon Composer `.icon` bundle, so the flat matte look can differ slightly from
the PNGs. A Liquid Glass icon is not generated; it would use the layer SVGs
`brand/out/*/{base,texture,mark}.svg`.
